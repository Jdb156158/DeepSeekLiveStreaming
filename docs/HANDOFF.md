# 制作流程与接手指南

本指南记录当前实现，而不是要求后来者把所有探索版本重做一遍。主体验是 Mac 本机的“扶砖小院 + 同页 AI 聊天”。截至 2026-11-07，代码与生成素材可以从仓库恢复，第三方模型和运行时由部署脚本下载。

## 1. 当前成品与未完成边界

已经实现：

- Live2D 大肥鱼、九套背景切换、太阳伞和小板凳休息角。
- 免费手动指令推倒1～6号砖；六排分别4～9块，连续倒下，角色排队逐块扶好。
- 收膝浅半蹲；完成后回凳坐下看手机，有新任务时连续起身。
- 在同一小院里聊天、朗读、语音口型、字幕、停止说话和模型配置。
- 本地 Qwen2.5 0.5B；可选 DeepSeek API；Edge TTS / Mac 中文语音回退。
- 原海底聊天预览和纯净场景继续可用。

没有实现：真实抖音弹幕采集、账号登录、礼物触发、真实推流、云部署、多人隔离、跨页面同步游戏状态、聊天控制游戏动作、小院纯净推流页。不要从已有 UI 推断这些能力已完成。

本地聊天服务有共享历史和单请求锁，不是多租户后端。当前聊天记录及游戏进度不会保存到浏览器持久存储；背景选择会保存。后端会保留进程内最近几轮对话，刷新页面不等于清空后端历史。

## 2. 技术结构与文件入口

```text
Mac 浏览器
  ├─ /bricks.html → bricks.mjs → DominoGame / repair-motion / scenes
  │                         └─ PixiJS + Live2D + 同一角色音频分析口型
  └─ / 或 /stage → app.js（保留的海底预览）
            ↓ HTTP / WebSocket
       server.py :18080
         ├─ /api/chat → Qwen llama-server :18081 或 DeepSeek API
         ├─ 语音合成 → Edge TTS，失败再用 Mac say + afconvert
         └─ /api/game/voice → 固定扶砖短台词
```

| 文件 | 职责与修改位置 |
| --- | --- |
| `server.py` | 人设、共享上下文、模型调用、语音、请求取消代次、状态及接口 |
| `web/bricks.html` | 小院控制台、聊天表单、九景选择和游戏操作；当前主页面 |
| `web/bricks.mjs` | Pixi 场景、投影、牌体绘制、角色控制、聊天 UI、音频优先级 |
| `web/domino-engine.mjs` | 纯规则与时间推进，不依赖 DOM、音频或语言模型 |
| `web/repair-motion.mjs` | 1.4秒扶砖时序、浅半蹲与坐姿网格变形 |
| `web/scenes.mjs` | 九套背景元数据、配色和素材路径 |
| `web/bricks.css` | 小院视觉与聊天布局，限定小院作用域 |
| `web/index.html` / `web/app.js` / `web/style.css` | 原海底聊天预览；不要为小院需求顺手替换 |
| `scripts/bootstrap.py` / `scripts/run.py` | 下载恢复与 Mac 服务生命周期 |
| `tests/domino-engine.test.mjs` / `tests/run.mjs` | 可独立执行的15项规则和姿态几何测试 |
| `web/art/*-prompt*.json` | 最终图片生成提示词与素材文件名 |

前端没有 npm 构建步骤。浏览器使用本机下载的 Pixi / Cubism，Python 提供静态文件。Node 仅是测试工具。

## 3. 实际制作过程

### 第一步：调研并建立原版预览

参考 `zbsdsb/dafeiyu-ai-vtuber`，拆出角色渲染、文本对话、TTS、口型和推流画面几部分。调研记录在根目录 `抖音AI宠物直播技术调研.md`。模型与运行时通过固定参考 commit 下载，未修改原始 Live2D 文件。

先完成海底预览 `/`，用本地 Qwen 替代缺少 Key 的云模型，保留 DeepSeek 配置入口。语音优先在线晓晓，失败时使用 Mac 婷婷；Web Audio 分析音量推动嘴巴开合，字幕按音频时长近似展开。此阶段没有连接抖音。

### 第二步：增加独立的免费扶砖玩法

新建 `/bricks.html`，不替换原页面。将输入识别、队列、连倒、移动、修复、暂停和重置写入纯 `DominoGame`；前端只消费状态、绘图与播放反馈。

指令接受1～6号及中文号码，重复推倒未修好的同一排会被拒绝，其他排按顺序排队。规则不依赖模型输出，LLM 延迟不会阻塞砖块动画。原来每排9块，后续按用户要求改成4～9块阶梯排列。

### 第三步：建立地面与场景布置

最初地板和砖块有悬浮感，改为所有对象共用1000×1000逻辑世界和同一投影：

```text
perspective = 1 / (1 + z * 0.065)
x = 590 + (worldX - 3.1) * 104 * perspective + z * 5
y = 830 - z * 68 * perspective - height * 100 * perspective
```

砖排尺寸、号码牌、接触阴影、人物工作点都使用这套投影。前端按容器缩放整个世界，避免只缩背景或只缩角色。六排整体右移，为左侧休息角腾出空间；不要靠另加悬浮台板修空间关系。

### 第四步：背景从六套卡通扩展到三套像素风

先生成海边小院，再增加樱花、蘑菇森林、糖果、雪顶、星光六套。用户认为过于圆润，要求额外加入三套二次元像素风，同时保留原六套，于是增加像素海边、像素樱庭、像素天台。

`SCENES` 提供元数据，切换只更新背景纹理和标题，不重置游戏。像素纹理用最近邻采样，六套原图保持线性采样。图片不含人物和砖，这些由运行时代码叠加。生成提示词与旧素材均保留。

### 第五步：修正多米诺倒地形态

早期倒地形态不自然，改为从底边旋转真实的修长牌体，牌面表情随同一平面旋转。倒下先加速，再由相邻牌面约束停止角；最后一块完全平躺，前面的牌逐块搭压。

接触关系由 `contactAngle(nextAngle)` 计算；参考论文链接在 `DESIGN.md`。当前每排按自己的实际长度建立 `FALLEN_ANGLES`。不要给短排沿用最长排的末角或硬编码固定9块。这里是几何动画，不是完整刚体摩擦仿真。

### 第六步：扶砖动作从弯腰改为收膝浅半蹲

用户先否定僵硬直立扶砖，随后否定大幅弯腰和外八字蹲。最终保留浅半蹲：脚底固定，重心下降约身高8.5%，双膝轻收但不交叉，上身前倾最多约7°。

`repairPose()` 将每块1.4秒分成下蹲、伸手、抬砖和站起；抬砖必须在伸手到位后开始。原生肩、肘、腕、低头及眼球参数配合网格变形。

`core.update` 包装层每帧先恢复 SDK 原顶点、执行 SDK 更新，再叠加当前姿态，防止逐帧累积变形。修改可见网格时也需通知裁切网格：`drawables.dynamicFlags[i] |= 32`。不要修改纹理来伪造姿势，不要只压扁整个人物。

### 第七步：按要求隐藏画面内作者文字

小院每帧设置模型原生 `Paramcol_3=1`，隐藏角色身前说明文字，并移除小院底部署名元素。原素材不改，作者和第三方来源仍在 `THIRD_PARTY_NOTICES.md`。原海底预览的署名行为不随小院修改。

### 第八步：太阳伞、躺椅探索后改为小板凳坐姿

先生成蓝白太阳伞和蓝白躺椅，并制作靠躺看手机、收到任务起身、任务完成返回的状态链。用户认为椅子与深蓝角色混色，将躺椅改为奶油/蜜桃色，旧图保留。

随后发现靠躺缩小、旋转后角色不清楚，将画布提升为2倍分辨率，取消休息时额外缩小。用户最终选择坐小板凳：生成浅木凳 `rest-stool.png`，取消人物整体旋转，用 `seatedVertices()` 下沉髋部、折叠腿部、并膝和固定双脚，上身比例保持。手机由 Pixi Graphics 绘制并重新对齐。

状态链为 `idle → rising → ready → moving → repairing → returning → settling → idle`。起身/坐下约0.65秒；回程或坐下中途的新任务可连续打断。引擎字段 `actor.recline` 沿用历史命名，当前含义是休息姿态进度0～1，不意味着仍有躺姿。

### 第九步：聊天整合进小院，而不是跳回海底页面

用户明确要求在小院里也能聊天。聊天区放在控制台最上方，顶部链接改为本页 `#garden-chat`。

复用后端 `/api/chat`，小院直接处理 HTTP 返回结果；原海底页面仍使用 WebSocket 广播。两页共享模型配置与后端历史。小院使用已有 `speechAudio` 和 `analyser`，让当前角色边走/扶砖/坐着边说话。

聊天期间抑制固定游戏吐槽与泡泡覆盖；回复结束后短暂保留字幕优先级。`chatRequest` 防止已取消的旧回复重新播放，`voiceGeneration` 阻止失效的固定短台词播放。`BroadcastChannel('fish-preview-audio')` 保证最新开启声音的一页取得音频播放权。不要再引入第二个角色或第二套同时发声的音频播放器。

“暂停/重置小院”和“停止说话”是不同操作。前者只影响游戏，后者会停止当前音频并调用后端 `/api/stop`。后端以代次丢弃取消结果，不保证中断正在进行的远端 HTTP 推理；原请求收尾前可能仍占据共享请求锁。

### 第十步：1号最短，6号最长

用户要求从1到6逐渐变长，最终设为4、5、6、7、8、9块。保持前端、号码牌、砖尺寸、间距及最长排范围，后端形成阶梯。

`ROW_BRICK_COUNTS` 是块数来源。渲染对象、地面阴影、连倒时长、停止角、扶砖终点和面板计数都按实际数组长度处理。新增六排全队列测试，累计应为39块。

WebView 实测曾继续使用旧 JS 模块；为入口与引擎 import 增加 `?v=20261107-rows`。如果规则和画面不一致，先核对实际加载版本，不要为迁就缓存修改正确规则。

## 4. 已验证的结果

- 15项自动规则/几何检查通过。运行 `node tests/run.mjs`。
- 浏览器里短排1号和最长6号各完成一次，累计13块、倒下0、队列为空，并回到坐凳。
- 真实本地 AI 回复、晓晓配音与 `repairing` 同时存在，字幕出现在小院。
- 朗读、停止、停止后再次聊天、Enter发送、暂停/重置不误停聊天已检查。
- 九套背景保留，1280px桌面及390px窄屏布局经过检查。
- 历史录制和开发截图在 `.local/`，没有随仓库分发；不能把文档中的本机截图路径当成新部署必须具备的资源。

这些检查不代表已完成抖音直播验收、长时间运行稳定性、云部署或商业素材授权。完整逐次记录见 `Verification/README.md`。

## 5. 继续开发时怎么改

| 需求 | 优先修改 | 需要验证 |
| --- | --- | --- |
| 改每排长短 | `ROW_BRICK_COUNTS` 及规则测试 | 总数、末块平躺、任务结束、计数、阴影与画面 |
| 调半蹲或坐姿 | `repair-motion.mjs`，再看 `bricks.mjs` 参数与摆位 | 脚不滑、膝不交叉、衣裙比例、裁切和恢复 |
| 换背景或道具 | `SCENES` / `web/art` / 道具坐标 | 九套保留、透明度、地面接触、不挡工作动作 |
| 调聊天行为 | `bricks.mjs` 聊天/音频区域，必要时 `server.py` | 重复发送、停止代次、游戏语音优先级、原页面音频归属 |
| 换云模型 | 后端 `complete()` 和配置表单 | 不回显Key、模型错误、无内容、超时及取消 |
| 接抖音弹幕 | 新采集适配层，调用明确的游戏/聊天入口 | 真实来源、去重、限流、重连、人工停止及平台实际验收 |
| OBS/真实开播 | 另实现小院纯净场景与采集/推流接线 | 画面与音频路由、前后台、权限与实际平台推流 |

不要为接手准备去删除旧背景/旧躺椅，不要恢复用户否定的八字蹲，不要把小院 UI 变成只能返回另一页才能聊天。

## 6. 接手后的第一轮

1. 读 `AGENTS.md` 与本文，核对 `git status`，尊重本机未提交修改。
2. 按 `DEPLOYMENT.md` 恢复未入库的下载与运行依赖。
3. 打开 `/api/status` 和 `/bricks.html`，确认当前模型、角色及块数。
4. 跑规则测试并实际查看当前页面；不要仅凭旧截图判断现状。
5. 明确这次需求的验收点，只修改相应模块，完成后记录实际检查结果。
